# Research Findings for 001-training-log-bot

## R-01: Технологический стек (Язык/Фреймворк)

- **Решение**: Python с библиотекой `aiogram`.
- **Обоснование**: Выбор основан на популярности `aiogram` для разработки Telegram-ботов на Python, его асинхронной природе, обширной документации и активном сообществе. Это обеспечит быструю и эффективную разработку, а также хорошую поддержку асинхронных операций, что критично для отзывчивого бота.
- **Рассмотренные альтернативы**: Go / telebot (отмечена высокая производительность, но потенциально большая сложность разработки для MVP), Node.js / node-telegram-bot-api (отмечена хорошая асинхронность, но экосистема для БД может быть менее зрелой).

## R-02: База данных

- **Решение**: PostgreSQL.
- **Обоснование**: PostgreSQL является оптимальным выбором благодаря нативной поддержке типа данных `timestamptz`, что соответствует функциональному требованию FR-008 о хранении времени в UTC с учетом временных зон. Это надёжная реляционная СУБД, хорошо подходящая для структурированных данных, таких как пользователи, тренировки и подходы.
- **Рассмотренные альтернативы**: MySQL / MariaDB (требуют дополнительной настройки для полноценной работы с часовыми поясами), SQLite (не подходит для конкурентного доступа и масштабирования).

## R-03: Среда развертывания

- **Решение**: Docker-контейнер на виртуальном сервере (VPS).
- **Обоснование**: Использование Docker обеспечит консистентность среды разработки и продакшна, упростит развертывание и управление зависимостями. Размещение на VPS дает полный контроль над инфраструктурой, высокую гибкость и возможность оптимизации затрат.
- **Рассмотренные альтернативы**: Heroku (упрощенное развертывание, но выше стоимость и меньше контроля), Serverless (экономично при низкой нагрузке, но может усложнить управление состоянием сессий).
