# Актуальная спецификация проекта TG Training Log Bot

**Дата обновления:** 2026-01-16  
**Источник истины:** код в `src/`, схема БД `docs/db/schema.dbml`, ТЗ/изменения `docs/UI.md`, `docs/tmp/*`.

---

## 1) Краткое описание и цель
Telegram-бот для ведения тренировочного журнала. Пользователь управляет тренировками, записывает подходы, ведёт свой справочник тренажёров/упражнений и может экспортировать данные в Google Sheets для аналитики. Основной фокус — корректная история нагрузок с фиксированием snapshot мышц/зон на момент выполнения подхода.

---

## 2) Роли и доступ
- **Пользователь**: работает с ботом после одобрения регистрации.
- **Администратор**: подтверждает/отклоняет запросы регистрации.

Доступ к функциям закрыт по флагу `users.is_registered = true`.

---

## 3) Архитектура и потоки
**Clean Architecture**: `domain` (модели) → `application` (use cases, DTO) → `infrastructure` (БД, Telegram, Google Sheets).

**Middleware цепочка** (см. `src/main.py`):
1. Logging (correlation_id, user_id, chat_id, update_id)
2. Database (session per request + commit/rollback)
3. Dependency Injection (репозитории + use cases)
4. Idempotency (dedup по `update_id`)
5. Registration Check (закрытый доступ)
6. Error Handling (глобальная обработка)

**Idempotency:** через `processed_updates` и `IdempotencyMiddleware` (savepoint, дедуп по `update_id`).

## 4) Основные сценарии и бизнес-логика

### 4.1 Регистрация
**Команда/UX:** `/start` и кнопка “Зарегистрироваться”.  
**Логика:**
- Если `user.is_registered = true` → показывается главное меню.
- Если пользователь существует, но не зарегистрирован → сообщение “ожидает одобрения”.
- Новый пользователь отправляет описание → админ получает кнопки “Одобрить/Отклонить”.
- **Approve** → `is_registered = true`, уведомление пользователю.
- **Reject** → запись удаляется, уведомление пользователю.

### 4.2 Главное меню
Кнопки зависят от активной тренировки:
- **Нет активной тренировки:** `[ ▶️/🏋️ Начать тренировку ]`
- **Есть активная тренировка:** `[ ⏹️/✅ Завершить ] [ ❌ Отменить ]` + `[ 📝 Записать подход ]`

### 4.3 Управление тренировкой
**Команды:** `/workout_start`, `/workout_end`, `/record_set`.  
**Кнопки:** “Начать тренировку”, “Завершить тренировку”, “Отменить тренировку”.

**Старт тренировки:**
- Проверка: у пользователя есть хотя бы один активный (не архивный) тренажёр.
- Если активная сессия уже есть → отказ.
- Иначе создаётся `workout_sessions` с `started_at`, `ended_at = null`.

**Завершение тренировки:**
- Если нет подходов в активной тренировке → просим либо добавить подходы, либо отменить.
- Иначе устанавливается `ended_at`.

**Отмена тренировки:**
- Если подходов нет → отмена без подтверждения, сессия удаляется.
- Если подходы есть → подтверждение, после согласия удаляются все подходы + сессия.

### 4.4 Запись подхода
**UI-flow:** выбор тренажёра → настройка веса/повторов/RIR → сохранение.  
**Логика:**
- Запись возможна только при активной тренировке.
- Машина должна существовать, принадлежать пользователю, не быть архивной.
- При сохранении создаётся `set_entries` + **snapshot**:
  - `set_entry_zones` (зоны тренажёра на момент записи)
  - `set_entry_muscles` (мышцы тренажёра на момент записи)
- Есть “быстрый выбор” последних тренажёров (по истории подходов), поиск по имени.
- Параметры подхода: `weight`, `reps`, `rir`.  
  - `rir` в диапазоне 0..5, где `0` означает отказ; значение по умолчанию — `2`.
  Валидация через DTO (`weight > 0`, `reps > 0`).

### 4.5 Управление тренажёрами
**Сценарии:** создание, просмотр, редактирование, архивация.  
**Логика:**
- Имя тренажёра уникально среди **активных** тренажёров пользователя.
- Тренажёр может иметь 0..N зон и 0..N мышц.
- Зоны — быстрый UX, мышцы — точная разметка.
- При редактировании можно менять имя, фото, зоны, мышцы, статус архивности.

### 4.6 Библиотека тренажёров
**Сценарии:** выбор из глобальной библиотеки и создание пользовательской копии.  
**Логика:**
- Библиотека хранит канонические тренажёры и их разметку по зонам/мышцам.
- Добавление из библиотеки создаёт **новый** пользовательский тренажёр (`machines`) с копированием разметки.
- Поле `machines.library_machine_id` указывает на источник из библиотеки, но дальнейшие правки независимы.
- Один и тот же библиотечный тренажёр можно добавить несколько раз.
- Если имя уже занято среди активных тренажёров, создаётся уникальное имя с суффиксом `(N)`.
- Поиск работает по `name_ru` и алиасам библиотечного тренажёра.

### 4.7 Справочники мышц и зон
**Источник справочника:** `docs/db/muscle_reference_zones_muscles.yaml`.  
**Скрипт наполнения:** `scripts/seed_muscles.py`.

### 4.8 Экспорт в Google Sheets
**Настройка:** пользователь отправляет URL таблицы; сохраняются `google_sheet_url`, `spreadsheet_id`.  
**Доступ:** сервисный аккаунт, пользователь выдаёт Editor.  
**Экспортируемые листы:**
- **Append-only:** `LOG_SETS`, `LOG_MUSCLES`
- **Обновляемые:** `REF_MACHINES`, `REF_ZONES`, `REF_MUSCLES`, `REF_ZONE_MUSCLES`
**Идемпотентность:** по `users.last_exported_set_id` (не дублировать `set_id`).
**Колонки подходов:** `LOG_SETS` и `LOG_MUSCLES` содержат `rir` вместо `is_failure`.

## 5) Доменная модель
Сущности (см. `src/domain/models.py`):
- `User`: Telegram-пользователь, статус регистрации, настройки Google Sheets, timezone.
- `MuscleZone`, `Muscle`, `MuscleZoneMuscle`: справочник “зона↔мышца” (M:N).
- `Machine`: тренажёр пользователя, пометки зон/мышц, `is_archived`.
- `MachineZone`, `MachineMuscle`: связи тренажёра с зонами/мышцами.
- `MachineLibrary`: библиотечный тренажёр (каноническое название, разметка).
- `MachineLibraryAlias`, `MachineLibraryZone`, `MachineLibraryMuscle`: связи и алиасы библиотеки.
- `WorkoutSession`: тренировочная сессия, `started_at`, `ended_at`.
- `SetEntry`: подход (вес/повторы/RIR), привязан к сессии и тренажёру.
- `SetEntryZone`, `SetEntryMuscle`: snapshot зон/мышц на момент подхода.
- `ProcessedUpdate`: дедупликация Telegram `update_id`.

## 6) Модель данных и ключевые инварианты
**Схема:** `docs/db/schema.dbml`.

Ключевые правила:
- `users.telegram_id` уникален.
- Одна активная сессия на пользователя (`ended_at is null`) — в бизнес-логике.
- `set_entries` создаются только в рамках активной сессии.
- Snapshot зон/мышц создаётся **всегда** при создании подхода.
- История подходов **не меняется** при редактировании тренажёра.
- `machines.is_archived = true` исключает использование в записи подходов.
- `machines.library_machine_id` может быть `null` и не влияет на логирование.
- `processed_updates.update_id` защищает от повторной обработки.

## 7) UX и UI (актуальные состояния)
**Управление тренировкой (из `docs/UI.md`):**
- Нет активной тренировки → кнопка “Начать тренировку”.
- Активная тренировка → “Завершить” + “Отменить”.
- Отмена без подходов — сразу; с подходами — подтверждение.

**Запись подхода:**
- Выбор тренажёра (с недавними и поиском).
- Редактор параметров (кнопки изменения + ручной ввод).
- Сохранение → сообщение об успехе.

## 9) НФТ и надёжность
- Идемпотентность Telegram updates через `processed_updates`.
- Транзакции per-request (DatabaseMiddleware).
- Валидация пользовательского ввода через Pydantic DTO.
- Структурированные логи с корреляцией (LoggingMiddleware).
- Глобальная обработка ошибок (ErrorHandlingMiddleware).
- Автопрогон Alembic миграций при старте.
