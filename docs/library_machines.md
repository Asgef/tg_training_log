## ТЗ: Библиотека тренажёров для Telegram-бота

### 1) Цель

Добавить в приложение **глобальную библиотеку тренажёров**, из которой пользователь может быстро добавлять тренажёры себе в список уже **с предзаполненной разметкой** (мышечные зоны и/или мышцы). Пользовательские тренажёры остаются редактируемыми и независимыми от библиотеки.

---

### 2) Термины

* **Тренажёр (библиотечный)** — шаблон (каноническая запись в библиотеке).
* **Тренажёр (пользовательский)** — запись пользователя в `machines`, используемая при логировании подходов.
* **Мышечная зона** — термин бодибилдинга (список хранится в `muscle_zones`).
* **Мышца** — конкретная мышца (список хранится в `muscles`).

---

### 3) Требования к данным (модель)

#### 3.1 Новые сущности

1. **`machine_library`** — библиотека тренажёров
   Поля:

* `id` (PK)
* `name_ru` (unique, text) — каноническое русское имя тренажёра
* `created_at` (timestamptz)
* `updated_at` (timestamptz)

2. **`machine_library_aliases`** — алиасы/синонимы (опционально, на старте могут быть пустые)
   Поля:

* `id` (PK)
* `machine_library_id` (FK → `machine_library.id`)
* `alias` (text)
* `created_at`
* `updated_at`
  Требование: не допускать дубликатов алиасов (глобально или в рамках одного тренажёра — на усмотрение реализации).

3. **`machine_library_zones`** — разметка библиотечного тренажёра зонами по умолчанию
   Поля:

* `machine_library_id` (FK)
* `zone_id` (FK → `muscle_zones.id`)
* `created_at`
* `updated_at`
  Требование: уникальность пары (`machine_library_id`, `zone_id`).

4. **`machine_library_muscles`** — разметка библиотечного тренажёра мышцами по умолчанию
   Поля:

* `machine_library_id` (FK)
* `muscle_id` (FK → `muscles.id`)
* `created_at`
* `updated_at`
  Требование: уникальность пары (`machine_library_id`, `muscle_id`).

#### 3.2 Изменение существующей сущности

Таблица **`machines`** (пользовательские тренажёры) расширяется:

* `library_machine_id` (nullable FK → `machine_library.id`)

Назначение: хранить связь “создано из библиотечного тренажёра”.

---

### 4) Поведение системы (логика)

#### 4.1 Создание пользовательского тренажёра из библиотеки

При добавлении пользователем тренажёра из библиотеки система должна:

1. Создать новую запись в `machines` для данного пользователя.
2. Установить `machines.library_machine_id` на выбранный библиотечный тренажёр.
3. Скопировать разметку из библиотеки:

   * из `machine_library_zones` → в `machine_zones`
   * из `machine_library_muscles` → в `machine_muscles`

**Важно:** после создания пользовательский тренажёр становится полностью независимым от библиотеки.

#### 4.2 Редактирование пользовательского тренажёра, созданного из библиотеки

Пользователь должен иметь возможность:

* изменить название тренажёра;
* изменить зоны;
* изменить мышцы;
* добавить/заменить фото. (пока не функционирует, реализуем позже)

Эти изменения:

* применяются **только к пользовательскому тренажёру** (`machines` и его связям),
* **не изменяют библиотеку**,
* не должны влиять на другие пользовательские тренажёры, созданные из того же шаблона.

#### 4.3 Повторное добавление одного и того же библиотечного тренажёра

Пользователь может добавить один и тот же библиотечный тренажёр несколько раз.
Каждое добавление создаёт **новую** запись в `machines` со своей дальнейшей независимой разметкой.

---

### 5) UI требования

#### 5.1 Добавление тренажёра

В интерфейсе добавления тренажёра должны быть доступны два пути:

* **«Добавить из библиотеки»**
* **«Создать вручную»**

#### 5.2 Выбор библиотечного тренажёра

При выборе “из библиотеки” бот показывает:

* список библиотечных тренажёров;
* поиск по названию (по `name_ru` и при наличии алиасов — по `aliases`).

#### 5.3 Карточка библиотечного тренажёра перед добавлением

Перед подтверждением добавления бот должен показать:

* название тренажёра;
* список зон по умолчанию;
* список мышц по умолчанию;
  и кнопки:
* **«Добавить себе»**
* **«Назад»**

---

### 6) Требования к совместимости с логированием подходов

* Логирование подходов продолжает работать только с `machines` (пользовательскими тренажёрами).
* Наличие или отсутствие `library_machine_id` не влияет на запись подходов.
* При формировании snapshot-записей (`set_entry_zones` / `set_entry_muscles`) используется актуальная разметка пользовательского тренажёра.

---

### 7) Администрирование библиотеки

* На старте алиасы могут быть не заполнены, но таблица и поддержка поиска по алиасам должны быть заложены.

### 8) Критерии готовности (DoD)

Считается выполненным, если:

1. В БД присутствуют таблицы библиотеки и связей, а в `machines` добавлено поле `library_machine_id`.
2. Пользователь может добавить тренажёр из библиотеки и получает пользовательский тренажёр с предзаполненными зонами/мышцами.
3. Пользователь может отредактировать такой тренажёр, и изменения не затрагивают библиотеку.
4. Один и тот же библиотечный тренажёр можно добавить несколько раз, получая независимые пользовательские копии.
5. Поиск по библиотеке работает по `name_ru` (и учитывает алиасы при их наличии).
