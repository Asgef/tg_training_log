## ТЗ: Рефакторинг метрики “отказ” → RIR (Reps In Reserve)

### 1) Цель

Заменить булевую метрику **`is_failure`** (“был отказ”) на метрику **`RIR`** — “сколько повторов осталось в запасе” (0 = отказ).
Обновить UI записи подхода, структуру БД и выгрузку датасета в Google Sheets.

> Допущение: сохранённые данные можно не мигрировать (бот ещё не в проде).

---

## 2) Требования к UI (запись подхода)

### 2.1 Экран “Укажи параметры подхода”

В форме записи подхода должен быть блок RIR:

**RIR: `X`**
Кнопки выбора:

* Быстрые значения: `[0] [1] [2] [3] [4] [5]`

Требования:

* RIR можно менять в любом порядке, как вес/повторы.
* Значение RIR отображается в тексте формы.
* По умолчанию предлагается `RIR = 2` (если пользователь ничего не выбрал).

### 2.2 Удаление “Отказ”

* Кнопки “✅ Да / ❌ Нет” для отказа удаляются из формы.
* Любые тексты/подтверждения, где фигурирует “отказ”, обновляются на “RIR”.

---

## 3) Требования к базе данных

### 3.1 Изменение таблицы `set_entries`

* Поле `is_failure` должно быть удалено.
* Добавить поле:

  * `rir int` **NOT NULL**
  * значение по умолчанию: `2`
  * допустимый диапазон: `0..5`

### 3.2 Диапазон RIR (фиксируем стандарт)

Для MVP установить диапазон:

* `rir` от `0` до `5`

Требования:

* `rir = 0` означает отказ (аналог старого `is_failure = true`)
* `rir > 0` означает “повторы в запасе”

### 3.3 Валидация на уровне БД

Добавить ограничение:

* `CHECK (rir >= 0 AND rir <= 5)`

---

## 5) Требования к миграциям

### 5.1 Alembic миграция

Необходимо создать миграцию, которая:

1. Удаляет `is_failure` из `set_entries`
2. Добавляет `rir int not null default 2`
3. Добавляет CHECK-constraint на диапазон

> Так как данных можно не сохранять, допускается “жёсткая” миграция без трансформации существующих строк.

---

## 6) Требования к логике сохранения подхода

При сохранении подхода:

* Вместо записи `is_failure` сохраняется `rir`.
* Если пользователь не выбрал RIR явно — используется значение по умолчанию.

---

## 7) Обновления справочных/экспортных сообщений

* Все пользовательские сообщения, где ранее отображался “Отказ”, заменить на “RIR”.
* В подтверждении сохранения подхода показывать: `RIR: X`.

---

## 8) Критерии готовности (DoD)

Считается выполненным, если:

* UI записи подхода содержит выбор RIR и не содержит “отказ”.
* В БД `set_entries` содержит `rir`, а поля `is_failure` нет.
* Экспорт в Google Sheets формирует `LOG_SETS` и `LOG_MUSCLES` с колонкой `rir` и без `is_failure`.
* Запись подхода корректно сохраняет `rir` и отражает его в подтверждении.
